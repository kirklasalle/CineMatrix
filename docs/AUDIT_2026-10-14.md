## 1. Executive Summary

CineMatrix Studio is a genuinely substantial, feature-rich application: a 9,300-line FastAPI backend exposing **60 REST endpoints**, a 5,000-line React 18 / TypeScript frontend, 15 test modules, and a curated 27-script sample library. The architecture is sound and the feature claims in the documentation are, with few exceptions, backed by real implementations.

However, this audit found a **release-blocking defect**: as of the baseline commit, the application **could not start from a clean install**. `backend/requirements.txt` was missing three packages that `main.py` imports at module load time, and declared the *wrong* Google SDK. Any user following the documented setup — and the GitHub Actions CI pipeline itself — would hit an `ImportError` before the server ever bound a port.

A **high-severity arbitrary file read** (path traversal) was also confirmed by live exploit in the sample-script loading endpoints.

The prior portfolio audit scored CineMatrix at **94.8 composite** with "0 security alerts". That assessment was based on static inspection and did not execute the code. This audit executed it. The revised, evidence-based scoring is in §6.

**All release-blocking and high-severity findings in this report have been fixed and verified as part of this audit.** See §7.

## 3. Findings

Severity key: 🔴 CRITICAL · 🟠 HIGH · 🟡 MEDIUM · ⚪ LOW

### 🔴 C-1 — Application cannot start from a clean install *(FIXED)*

`backend/requirements.txt` omitted packages imported at module load time by `backend/main.py`:

- `backend/video_engine.py:15-16` imports `cv2` and `numpy`; `main.py:36` imports `video_engine`. Neither `opencv-python` nor `numpy` was declared.
- `backend/providers/google_provider.py:2-3` uses the **new** Google GenAI SDK (`from google import genai`), which ships as the `google-genai` package. `requirements.txt` declared the **legacy, incompatible** `google-generativeai` package instead.

**Reproduced:**

```
ImportError: cannot import name 'genai' from 'google' (unknown location)
ModuleNotFoundError: No module named 'cv2'
```

**Blast radius:** every fresh install, the documented Quick Start, the desktop build (`build_desktop.py`), *and* the GitHub Actions CI pipeline (which installed `requirements.txt` then ran pytest) were broken. CI could not have been passing on `main`.

Also undeclared but imported lazily: `PyMuPDF` (`main.py:1492,1602`, `examples_service.py:446`), `pypdf` (`main.py:1504`). `main.py:1515` even instructs the user to install PyMuPDF — a package the project never declared.

### 🟠 H-1 — Arbitrary file read via sample-script path traversal *(FIXED)*

`POST /projects/{id}/load-example` and `POST /projects/create-with-example` took attacker-controlled `category` and `filename` values from the JSON body and joined them straight onto the examples directory with no containment check (`main.py:1591`, `examples_service.py:428`).

**Confirmed by live exploit** against the running app:

```
POST /projects/{id}/load-example  {"category": "../..", "filename": "README.md"}
→ 200 OK, file contents ingested into the project as a script
```

Any file readable by the server process on the same drive could be exfiltrated through the project/scene API. The `GET /examples/{category}/{filename}` route was incidentally protected by Starlette's path-segment routing, but the body-driven routes were not.

### 🟠 H-2 — Encryption fails open with a fixed development secret

`backend/crypto_utils.py:30-43` returns **plaintext** if encryption raises, and `crypto_utils.py:60-64` falls back to a hardcoded development secret plus a fixed salt when `STORYBOARD_SECRET_KEY` is unset. Provider API keys can therefore be persisted unencrypted without any signal to the operator. Encryption should fail closed and refuse to start without a configured secret in non-development mode.

*Status: documented, scheduled for Phase 11 (§7 roadmap). Not changed in this pass — it alters key-storage behaviour and requires a migration path for already-persisted keys.*

### 🟡 M-1 — Unauthenticated destructive endpoint

`POST /system/shutdown` (`main.py:155-169`) calls `os._exit(0)` with no authentication. Acceptable for a loopback-only desktop app — which is the intended deployment — but it means the service must **never** be bound to a non-loopback interface. Documented in `SECURITY.md` and `docs/STATUS.md`.

### 🟡 M-2 — Upload hardening gaps

`main.py:1468-1485` caps the read at 20 MB, but only *after* multipart parsing, and enforces no extension or MIME allow-list. CBZ/EPUB archives are expanded without entry-count, decompression-ratio, or path-safety limits (`main.py:1533-1544`), leaving a zip-bomb / zip-slip surface.

### 🟡 M-3 — Error responses leak internals

The global exception handler returns `{"detail": str(exc)}` (`main.py:94-105`), and several routes re-raise raw exception text as HTTP 500 detail. Filesystem paths, SQL fragments, and provider errors reach the client.

### 🟡 M-4 — Blocking work inside async request handlers

Most routes are `async def` but perform synchronous SQLAlchemy queries, ReportLab PDF generation, OpenCV video encoding, and WAV synthesis inline (e.g. `main.py:390-610`, `768-816`, `2170-2313`). This blocks the event loop. Batch generation runs unbounded inside the request lifetime with no job tracking, so long jobs can time out and leave partial state.

### 🟡 M-5 — Frontend lint pipeline was non-functional *(FIXED)*

`package.json` declared a `lint` script, but no ESLint configuration file existed anywhere in `frontend/`. `npm run lint` exited with `ESLint couldn't find a configuration file`. The project had been shipping with zero enforced lint coverage.

### 🟡 M-6 — Version strings drifted across four sources *(FIXED)*

`FastAPI(version="2.0.0")` (`main.py`), `/health` → `3.2.0`, `/` → `3.2.0`, `frontend/package.json` → `3.2.0`, `dist_release/version_manifest.json` → `3.2.0`. The OpenAPI schema advertised a version two majors behind the product.

### ⚪ L-1 — Orphaned modules

`memory_service.py` (37 LOC), `feedback_engine.py` (31 LOC), and `prompt_optimizer.py` (22 LOC) are not imported by `main.py` or any wired module — dead code. `genre_vault.py` and `concept_art_engine.py` are reachable only through dynamic imports in single code paths.

### ⚪ L-2 — No transaction rollback on failure paths

Sessions close in `finally`, but exception paths generally omit `db.rollback()` (e.g. `main.py:1436-1446`, `1468-1573`).

### ⚪ L-3 — N+1 queries on the projects list

`GET /projects` (`main.py:1412-1433`) issues 3–4 extra queries per project.

### ⚪ L-4 — No frontend tests

No test runner, no test script, no `*.test.*` files. The only frontend validation is `tsc` during build.

### ⚪ L-5 — Oversized components

`StoryboardGallery.tsx` (1,065 LOC) mixes data loading, SSE streaming, generation, exports, lightbox, and presentation. `Configuration.tsx` (789 LOC) and `App.tsx` (656 LOC) are similarly overloaded. Every component issues raw `fetch` calls; there is no shared API client, so status-check and error behaviour is inconsistent.

### ⚪ L-6 — Accessibility gaps

Icon-only buttons rely on `title` rather than `aria-label` (`App.tsx:633-637`, `StoryboardGallery.tsx:558,624,979`). Global numeric keyboard shortcuts intercept keys outside editable elements (`useNleKeyboardShortcuts.ts:28-96`).

### ⚪ L-7 — Windows-only browser discovery

`desktop_launcher.py:97-101` probes hardcoded `C:\Program Files...` Edge/Chrome paths, making the desktop launcher Windows-only in practice.

## 7. Remediation Plan

### Phase 0 — Release Blockers ✅ COMPLETE (this audit, v3.3.0)

| Item | Finding | Status |
|---|---|---|
| Complete and pin `requirements.txt`; swap to `google-genai`; add `requirements-dev.txt` | C-1 | ✅ Done |
| Containment check on all sample-script path resolution (`resolve_example_path`) | H-1 | ✅ Done |
| Add ESLint config; restore `npm run lint`; add `typecheck` + `lint:strict` scripts | M-5 | ✅ Done |
| Single-source `APP_VERSION`; align OpenAPI / `/health` / `/` / `package.json` | M-6 | ✅ Done |
| Repair CI: install dev requirements, add lint gate, move to Python 3.12 | C-1 | ✅ Done |
| Add 13 regression tests covering traversal, dependency contract, version consistency | — | ✅ Done |
| Full documentation rewrite: CHANGELOG, ROADMAP, API_REFERENCE, PRD, README, STATUS | D-1…D-11 | ✅ Done |

### Phase 11 — Security Hardening (next, target v3.4.0)

1. **Fail-closed encryption** (H-2) — refuse startup without `STORYBOARD_SECRET_KEY` outside dev mode; per-install random salt; migrate existing keys.
2. **Upload hardening** (M-2) — extension/MIME allow-list, pre-parse size limits, archive entry-count and decompression-ratio caps, zip-slip path validation.
3. **Sanitised error envelope** (M-3) — client-safe messages with a correlation ID; full detail to logs only.
4. **Shutdown authorisation** (M-1) — local token or explicit opt-in flag.
5. **Negative-path test suite** — upload abuse, provider failures, malformed archives.

### Phase 12 — Reliability & Performance (target v3.5.0)

1. Move blocking work off the event loop (M-4) — thread pool or background job queue for PDF, video, and audio generation.
2. Resumable batch generation with job IDs and progress polling.
3. Eliminate N+1 queries on `GET /projects` (L-3).
4. Consistent `rollback()` on all failure paths (L-2).
5. Endpoint-level integration tests for `main.py`, `storyboard_engine.py`, and the provider layer.

### Phase 13 — Frontend Quality (target v3.6.0)

1. Vitest + Testing Library; drive `lint:strict` to zero warnings (84 outstanding).
2. Extract a shared typed API client; delete duplicated `fetch` logic.
3. Split `StoryboardGallery`, `Configuration`, and `App` into hooks + presentational components (L-5).
4. Surface error states in every view; remove silent `console.error`-only failure paths.
5. Accessibility pass: `aria-label` on icon buttons, focus trapping, scoped shortcuts (L-6).

### Phase 14 — Packaging & Portability (target v4.0.0)

1. Cross-platform browser discovery in `desktop_launcher.py` (L-7).
2. Remove orphaned modules or wire them in (L-1).
3. Reproducible desktop build with a dependency lock file and signed release artefacts.
4. Linux/macOS verification of the PDF font-embedding path flagged by the prior portfolio audit.
